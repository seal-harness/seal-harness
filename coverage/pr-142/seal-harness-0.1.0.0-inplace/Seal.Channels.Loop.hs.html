    2 -- | The shared inbox-driven channel loop, used by both Signal and Telegram
    3 -- channels (and any future inbox-driven channel). The loop pulls
    4 -- @(MessageSource, body)@ from 'chReceive', classifies via
    5 -- 'Seal.Routing.Route' (Layer-1 terse grammar + /tab commands BEFORE the
    6 -- /-command registry), dispatches slash commands via a 'ChannelCaps'
    7 -- adapter over the 'ChannelHandle', and routes plain messages to the
    8 -- supplied 'plainHandler' (which runs 'runTurn' with 'aeMessageSource' =
    9 -- @Just ms@). Terminates when 'chReceive' returns EOF.
   10 --
   11 -- The 'ChannelDeps' record bundles everything a channel turn needs to have
   12 -- parity with the web and CLI paths: the full ISA registry (including
   13 -- Untrusted execution opcodes, web fetch/search, harness ops, and
   14 -- AGENT_START), the WS broker for live transcript updates, and the harness
   15 -- + tmux + HTTP manager deps. This ensures every channel gets identical
   16 -- transcript logging and tool-call infrastructure.
   17 --
   18 -- == Tab-centric session model
   19 --
   20 -- Each conversation (a Telegram chat, a Signal conversation) has its own
   21 -- cursor into the shared tab list ('CursorStore'). On first message from
   22 -- a conversation, a new tab + session is created and the cursor is set.
   23 -- Subsequent messages resolve the session via the cursor → tab → SessionId
   24 -- path, NOT via a shared active-session ref. This means @/tab focus N@
   25 -- on one Telegram conversation only affects that conversation — other
   26 -- conversations keep their own cursor. The web frontend has no cursor; it
   27 -- sends to a specific session by id (the tab the user clicked).
   28 --
   29 -- Replies fan out to all channels focused on the session via the
   30 -- 'ReplyRegistry' — so a web-originated turn on a Telegram-session tab
   31 -- also delivers the reply to Telegram. A per-session write lock
   32 -- ('SessionLocks') serializes concurrent turns on the same session to
   33 -- prevent transcript corruption.

  216 -- | Build the channel 'TurnAdapter' for a given 'ChannelHandle' +
  217 -- 'ChannelCaps'. The channel adapter:
  218 -- * @taPreTurn@ — 'replySubscribe's the channel handle to the session's
  219 --   replies (so the post-turn fan-out delivers the assistant response to
  220 --   this channel) + 'replyFanoutMessage' mirrors the user's message to
  221 --   every OTHER subscribed channel (cross-channel mirroring, the handle's
  222 --   label).
  223 -- * @taChannelLabel@ — the session's 'smChannel' (an inbox session is
  224 --   always created on the channel its messages arrive on).
  225 -- * @taOnStop@ — 'Just' the reply fan-out so subscribed channels receive
  226 --   the final reply.
  227 -- * @taOnUserMessage@ — for /bg turns, 'Just' a 'broadcastTabs' refresh so
  228 --   the sidebar shows the session name as soon as the user message is
  229 --   durable; 'Nothing' for normal turns (the post-turn 'taPostTurn'
  230 --   refresh covers them).
  231 -- * @taPostTurn@ — 'broadcastTabs' so the sidebar reflects the new tab +
  232 --   the first-message snippet. Runs for both auto-tab and /bg paths.
  233 -- * @taStartWiring@ — the engine-owned 'TurnEngine.buildStartWiring' (W4
  234 --   collapsed the per-surface builders into this single one).
  235 mkChannelTurnAdapter :: ChannelDeps -> TurnDeps -> ChannelHandle -> ChannelCaps -> TurnAdapter
  236 mkChannelTurnAdapter deps td h caps = TurnAdapter
  237   { taCaps          = caps
  238   , taPreTurn       = \sid _meta t -> do
  239       _ <- replySubscribe (cdReplies deps) h sid
  240       replyFanoutMessage (cdReplies deps) sid (chLabel h) t
  241   , taChannelLabel  = smChannel
  242   , taOnStop        = Just . replyFanout (cdReplies deps)
  243   , taOnUserMessage = \meta -> if shouldAutoTab meta
  244                                  then Nothing
  245                                  else Just (broadcastTabs deps (cdTabs deps))
  246   , taPostTurn      = \_ _ -> broadcastTabs deps (cdTabs deps)
  247   , taStartWiring   = \sessionBackends sid appEnv eCfg operatorCeiling meta ->
  248       TurnEngine.buildStartWiring td sessionBackends sid appEnv eCfg operatorCeiling (smChannel meta)
  249   }

  307 -- | Build the channel's slash-command registry from a supplied base
  308 -- 'Registry' plus the channel-specific @bg@, @call@, @skill@, and @model@
  309 -- specs.
  310 --
  311 -- The channel-appended specs bind to the channel's per-session
  312 -- 'channelCallDispatcher' (which reads the conversation's cursor-resolved
  313 -- sid). Under @seal serve@, the supplied @registry@ is the WEB gateway's
  314 -- registry, whose @skill@ and @call@ specs bind to 'webCallDispatcher'
  315 -- (which reads the process-global @srActive@ ref). Without shadowing those
  316 -- out, a @/skill load@ issued from Telegram dispatches via the FIRST
  317 -- matching spec — the web one — and records the SKILL_LOAD entry on
  318 -- whatever session @srActive@ points at, NOT the Telegram conversation's
  319 -- session. The same hazard applies to @/model use@ (the core spec writes
  320 -- @srActive@'s session.json, not the conversation's). The channel-dispatcher
  321 --   versions must win, so drop any incoming spec whose primary name collides
  322 --   with a channel-appended spec before appending them. 'lookupSpec' returns
  323 --   the first match, so the appended channel specs then resolve correctly.
  324 --
  325 -- The @model@ spec is built from the channel's 'ProviderRuntime' + 'SealPaths'
  326 -- + broker (passed explicitly rather than reading the whole 'ChannelDeps' so
  327 -- the registry builder stays decoupled from the full deps record — the
  328 -- pure-registry tests don't need to construct a full 'ChannelDeps').
  329 buildChannelRegistry
  330   :: ProviderRuntime -> SealPaths -> Maybe StreamBroker
  331   -> SkillBackend -> BgRunner -> CallDispatcher
  332   -> IORef SessionId -> Registry -> Registry
  333 buildChannelRegistry pr paths mBroker skillBackend bgRunner callDispatcher sidRef registry =
  334   mkRegistry (baseSpecs <> channelSpecs)
  335   where
  336     channelSpecNames = ["bg", "call", "skill", "model"] :: [Text]
  337     baseSpecs = filter
  338       (\s -> let CommandName n = csName s in n `notElem` channelSpecNames)
  339       (registrySpecs registry)
  340     channelSpecs =
  341       [ backgroundCommandSpec bgRunner
  342       , callCommandSpec callDispatcher
  343       , skillCommandSpec skillBackend callDispatcher
  344       , modelCommandSpecForSession
  345           pr paths (readIORef sidRef)
  346           (mkModelTranscriptWriter paths mBroker)
  347       ]

  349 -- | The inbox-driven loop. Spawns the channel via the supplied bracket,
  350 -- pulls @(MessageSource, body)@ from 'chReceive', classifies via
  351 -- 'Seal.Routing.Route', and dispatches. Each conversation resolves its
  352 -- session via the cursor store (not a shared active-session ref). On
  353 -- first message from a conversation, a new tab + session is created.
  354 --
  355 -- The optional 'mkCaps' factory overrides the default 'mkHandleCaps'
  356 -- (e.g. Telegram's inline-keyboard 'ccPrompt'). 'Nothing' = use
  357 -- 'mkHandleCaps' (Signal + the generic numbered list).
  358 --
  359 -- The optional 'onCallback' hook is called before
  360 -- 'deliverNextAnswerResolved' — Telegram uses it to route callback_query
  361 -- button taps by 'AskId' (by-id delivery, NOT FIFO). 'Nothing' = no
  362 -- callback support (the body goes straight to 'deliverNextAnswerResolved').
  363 runChannelLoop
  364   :: (Channel c)
  365   => ChannelDeps
  366   -> ((c -> IO ()) -> IO ())
  367   -> (ChannelHandle -> SessionMeta -> Maybe MessageSource -> Text -> IO ())
  368   -> Registry
  369   -> PreprocessChain
  370   -> AskReplyStore
  371   -> TabsHandle
  372   -> Maybe (ChannelHandle -> AskReplyStore -> SessionId -> ChannelCaps)
  373   -> Maybe (ChannelHandle -> SessionId -> Text -> IO Bool)
  374   -> IO ()
  375 runChannelLoop deps withChannel plainHandler registry chain askReply tabsH mkCaps onCallback =
  376   withChannel $ \ch -> do
  377     let h = toHandle ch
  378     -- A mutable cell holding the originating conversation's active session
  379     -- id, updated each turn before any slash command is dispatched. The
  380     -- /bg runner reads it to key the confirmation ask to the conversation
  381     -- (not the fresh bg session), so the loop's deliverNextAnswer
  382     -- short-circuit consumes the next inbound message as the answer. The
  383     -- initial bottom is never read: the loop writes the real sid before
  384     -- any /bg dispatch.
  385     bgConvSid <- newIORef (error "bgConvSid: set before first dispatch" :: SessionId)
  386     let td = mkChannelTurnDeps deps
  387         bgRunner = mkBgRunner deps h askReply bgConvSid tabsH
  388         callDispatcher = channelCallDispatcher deps td h askReply bgConvSid
  389         registryWithBg = buildChannelRegistry
  390           (cdProvider deps) (cdPaths deps) (cdBroker deps)
  391           (bSkills (cdBackends deps)) bgRunner callDispatcher bgConvSid registry
  392     loop h registryWithBg bgConvSid
  393   where
  394     loop h reg bgConvSid = do
  395       (mSrc, body) <- chReceive h
  396       case mSrc of
  397         Nothing -> pure ()  -- EOF
  398         Just ms -> do
  399           let key = convKey ms
  400               bgRoute = isBgSlash body
  401           -- Resolve the conversation's session (create if first message).
  402           -- For a /bg command, take the headless path: the conversation needs
  403           -- an anchor session (its sid keys the bg runner's confirmation ask
  404           -- via bgConvSid below) but must NOT get a tab, since no turn ever
  405           -- runs on this session — a tab would surface as an empty
  406           -- conversation in the web sidebar. The bg turn itself runs on a
  407           -- separate, fresh bg session minted by mkBgRunner.
  408           mCursor <- cursorLookup (cdCursors deps) key
  409           meta <- case mCursor of
  410             Just tabRef -> do
  411               mMeta <- resolveTabSession deps tabRef
  412               case mMeta of
  413                 Just m  -> pure m
  414                 Nothing
  415                   | bgRoute  -> createConversationSessionHeadless deps key (msChannelKind ms)
  416                   | otherwise -> createConversationSession deps h key (msChannelKind ms) tabsH
  417             Nothing
  418               | bgRoute  -> createConversationSessionHeadless deps key (msChannelKind ms)
  419               | otherwise -> createConversationSession deps h key (msChannelKind ms) tabsH
  420           let sid = smId meta
  421           -- Record the conversation's active session so the /bg runner
  422           -- (dispatched below if this turn is a /bg) keys its confirmation
  423           -- ask to this sid. Updated every turn, before any slash-command
  424           -- dispatch.
  425           writeIORef bgConvSid sid
  426           -- For channels with callback support (Telegram), try the
  427           -- onCallback hook first (by-id delivery for button taps). If it
  428           -- returns True, the body was a callback + delivered; continue
  429           -- the loop. Otherwise, fall through to deliverNextAnswerResolved.
  430           mCallbackHandled <- case onCallback of
  431             Nothing -> pure False
  432             Just cb -> cb h sid body
  433           delivered <-
  434             if mCallbackHandled
  435               then pure True
  436               else snd <$> deliverNextAnswerResolved askReply sid body
  437           if delivered
  438             then loop h reg bgConvSid
  439             else do
  440               let handleCaps = case mkCaps of
  441                     Nothing -> mkHandleCaps h askReply sid
  442                     Just f  -> f h askReply sid
  443               case Route.route body of
  444                 Right (Route.Focus idx) -> do
  445                   _ <- focusTabH tabsH idx
  446                   tl <- snapshotTabs tabsH
  447                   case lookupTabByIndex tl idx of
  448                     Just tab -> cursorSet (cdCursors deps) key (tRef tab)
  449                     Nothing -> pure ()
  450                   chSend h ("focused tab " <> T.singleton (tabIndexToChar idx))
  451                   loop h reg bgConvSid
  452                 Right (Route.Inject idx payload) -> do
  453                   _ <- focusTabH tabsH idx
  454                   void (forkIO (plainHandler h meta (Just ms) payload))
  455                   loop h reg bgConvSid
  456                 Right (Route.TabCommand tsc) -> do
  457                   _ <- handleTabCommand h tabsH tsc
  458                   loop h reg bgConvSid
  459                 Right Route.CurrentTab -> do
  460                   tl <- snapshotTabs tabsH
  461                   case mCursor >>= lookupByRef tl of
  462                     Just t  -> chSend h (renderCurrentTab t)
  463                     Nothing -> chSend h "no current tab"
  464                   loop h reg bgConvSid
  465                 Right (Route.NewSession _args) -> do
  466                   _ <- handleNewSession deps h tabsH (msChannelKind ms) meta
  467                   loop h reg bgConvSid
  468                 Right (Route.SlashCommand _) -> do
  469                   d <- ingest reg chain (RawInbound body)
  470                   case d of
  471                     DispatchAction a -> do
  472                       eResult <- withExceptionLogging (cdLogger deps) Nothing "slash command" $
  473                         runCommandAction a handleCaps
  474                       case eResult of
  475                         Left errMsg -> chSend h errMsg
  476                         Right _     -> pure ()
  477                       loop h reg bgConvSid
  478                     ShowText t       -> chSend h t >> loop h reg bgConvSid
  479                     PlainMessage t   -> void (forkIO (plainHandler h meta (Just ms) t)) >> loop h reg bgConvSid
  480                     Rejected msg     -> chSend h msg >> loop h reg bgConvSid
  481                 Right (Route.Plain t) -> do
  482                   void (forkIO (plainHandler h meta (Just ms) t))
  483                   loop h reg bgConvSid
  484                 Left (Route.ParseError e) -> do
  485                   chSend h e
  486                   loop h reg bgConvSid

  488 -- | Build the per-turn 'ChannelCaps' for a channel handle.
  489 mkHandleCaps :: ChannelHandle -> AskReplyStore -> SessionId -> ChannelCaps
  490 mkHandleCaps h askReply sid = def
  491   { ccSend         = chSend h
  492   , ccPrompt       = \(AskPrompt q opts) -> do
  493       chSend h (formatQuestionWithOptions q opts)
  494       outcome <- askHumanWithOptions askReply sid q opts (const (pure ()))
  495       pure (fromRight "" outcome)
  496   , ccPromptSecret = fmap (fromRight "") . chPromptSecret h
  497   , ccStreaming    = chStreaming h
  498   }

  520 -- | Handle @\/new@ on an inbox channel: mint a fresh session from config
  521 -- defaults, rebind the conversation's current tab (if any) to the new sid,
  522 -- migrate every OTHER conversation cursor pointing at the old ref to the
  523 -- new ref (per the user's "a tab has one session at a time; all channels
  524 -- focused on the tab follow the rebind" model), and send the confirmation
  525 -- line. The old session is kept on disk (still in @/session list@).
  526 --
  527 -- Mirrors the CLI's @\/new@ path but lives at the loop level because the
  528 -- conversation key + cursor aren't available to a registry CommandAction
  529 -- (architect review issue C). The fresh @meta@ is NOT used to run a turn —
  530 -- the next inbound message's cursor lookup resolves to the new session
  531 -- automatically (the cursor migrate ensures that).
  532 handleNewSession
  533   :: ChannelDeps -> ChannelHandle -> TabsHandle
  534   -> ChannelKind -> SessionMeta -> IO ()
  535 handleNewSession deps h tabsH kind oldMeta = do
  536   -- Preserve the old session's provider/model/agent (so mid-session
  537   -- /model use changes survive /new). The new session gets a fresh id +
  538   -- timestamps; everything else is copied from the old meta.
  539   let channelLabel = channelKindToText kind
  540       oldSid = smId oldMeta
  541       oldRef = BoundSession oldSid
  542   newMeta <- newSessionMeta (cdPaths deps) (smProvider oldMeta) (smModel oldMeta)
  543                             channelLabel (smAgent oldMeta)
  544   saveSessionMeta (cdPaths deps) newMeta
  545   -- Rebind the tab (if any) bound to the old sid to the new sid.
  546   snap <- snapshotTabs tabsH
  547   case [ t | t <- tlTabs snap, tRef t == oldRef ] of
  548     []       -> pure ()  -- no tab bound to old sid; cursor-only swap below
  549     (tab : _) -> rebindTabH tabsH (tIndex tab) (BoundSession (smId newMeta)) >>= \case
  550       Left e  -> chSend h ("warning: /new tab rebind failed: " <> e)
  551       Right _ -> broadcastTabs deps tabsH
  552   -- Migrate every conversation cursor pointing at the old ref to the new
  553   -- ref (includes THIS conversation's cursor). Per the user's model: a tab
  554   -- has one session at a time; all channels focused on it follow the
  555   -- rebind to the new session.
  556   _count <- cursorMigrateAll (cdCursors deps) oldRef (BoundSession (smId newMeta))
  557   -- Migrate reply subscriptions from the old session to the new one so
  558   -- future fan-outs (including tab-close notifications) reach attached
  559   -- channels under the new session id.
  560   _n <- replyMigrateAll (cdReplies deps) oldSid (smId newMeta)
  561   chSend h
  562     ("new session " <> sessionIdText (smId newMeta)
  563        <> " (" <> smProvider newMeta <> "/" <> smModel newMeta <> ")"
  564        <> " — prior session " <> sessionIdText oldSid <> " kept in /session list")

  566 -- | Create a new session + tab for a conversation that has no cursor yet.
  567 -- Mints a 'SessionMeta' from config defaults, persists it, inserts a tab
  568 -- into the shared 'TabsHandle', and sets the conversation's cursor.
  569 createConversationSession
  570   :: ChannelDeps -> ChannelHandle -> (Text, Text) -> ChannelKind
  571   -> TabsHandle -> IO SessionMeta
  572 createConversationSession deps _h key kind tabsH = do
  573   cfg <- cdConfig deps
  574   (mAgent, mProv, mModel) <- resolveDefaultAgent (bAgentDefs (cdBackends deps)) cfg
  575   let (cfgProv, cfgModel) = defaultSessionSelection cfg
  576       provider = fromMaybe cfgProv mProv
  577       model    = fromMaybe cfgModel mModel
  578       channelLabel = channelKindToText kind
  579   meta <- newSessionMeta (cdPaths deps) provider model channelLabel mAgent
  580   saveSessionMeta (cdPaths deps) meta
  581   -- Bind the conversation's cursor to this session unconditionally. The
  582   -- cursor is what the loop's next-turn lookup (Loop.hs:278) uses to
  583   -- resolve the conversation's session; if it isn't set, the next message
  584   -- mints a brand-new session and orphans this one. Earlier this lived
  585   -- inside the 'Right _' branch below, so a full tab list (Left _) silently
  586   -- skipped cursor-binding — every subsequent turn from the conversation
  587   -- would mint a fresh session, never reusing this one.
  588   cursorSet (cdCursors deps) key (BoundSession (smId meta))
  589   r <- insertTabH tabsH (BoundSession (smId meta)) KindAi Nothing
  590   case r of
  591     Left _ -> pure ()  -- tab list full; session still works without a tab
  592     Right _ ->
  593       -- Push the new tab to any WS subscribers (the web frontend sidebar)
  594       -- so a channel-created tab surfaces immediately. No-op when cdBroker
  595       -- is Nothing (standalone signal/telegram without serve).
  596       broadcastTabs deps tabsH
  597   pure meta

  599 -- | Create a new session for a conversation WITHOUT inserting a tab or
  600 -- broadcasting to the sidebar. Used by the @/bg@ path (see 'isBgSlash')
  601 -- where the conversation needs an anchor session (its sid keys the bg
  602 -- runner's confirmation ask via 'bgConvSid') but must NOT surface an empty
  603 -- tab in the web sidebar — the @/bg@ turn runs headless on a fresh bg
  604 -- session, so a tab bound to this conversation session would never receive
  605 -- a turn and would appear dead. The cursor is always set (unlike
  606 -- 'createConversationSession', there is no tab-list-full failure mode to
  607 -- skip it on), so subsequent non-bg messages resolve to this session.
  608 createConversationSessionHeadless
  609   :: ChannelDeps -> (Text, Text) -> ChannelKind -> IO SessionMeta
  610 createConversationSessionHeadless deps key kind = do
  611   cfg <- cdConfig deps
  612   (mAgent, mProv, mModel) <- resolveDefaultAgent (bAgentDefs (cdBackends deps)) cfg
  613   let (cfgProv, cfgModel) = defaultSessionSelection cfg
  614       provider = fromMaybe cfgProv mProv
  615       model    = fromMaybe cfgModel mModel
  616       channelLabel = channelKindToText kind
  617   meta <- newSessionMeta (cdPaths deps) provider model channelLabel mAgent
  618   saveSessionMeta (cdPaths deps) meta
  619   cursorSet (cdCursors deps) key (BoundSession (smId meta))
  620   pure meta

  622 -- | Does an inbound body route to a @/bg@ slash command? Layer-1 routing
  623 -- ('Seal.Routing.Route.route') sends any @\/<other>…@ to 'SlashCommand'; this
  624 -- checks the command name is @"bg"@ (case-insensitive, matching the terse
  625 -- grammar's single-token form @\/bg@ or @\/bg <prompt>@). Used by the loop to
  626 -- pick the headless session-creation path, so @/bg@ does not mint a spurious
  627 -- empty tab for the conversation while still anchoring the bg runner's
  628 -- confirmation-ask key on the conversation's sid.
  629 isBgSlash :: Text -> Bool
  630 isBgSlash body =
  631   case Route.route body of
  632     Right (Route.SlashCommand rest) ->
  633       let cmd = T.toCaseFold (T.takeWhile (/= ' ') rest)
  634       in cmd == "bg"
  635     _ -> False

  637 -- | Push the current tab-list snapshot to WS subscribers (the web frontend
  638 -- sidebar). No-op when 'cdBroker' is 'Nothing' (standalone channels without
  639 -- @seal serve@). Call after any channel-side tab mutation so the frontend
  640 -- reflects the change without waiting for a web-originated turn.
  641 broadcastTabs :: ChannelDeps -> TabsHandle -> IO ()
  642 broadcastTabs deps tabsH =
  643   case cdBroker deps of
  644     Nothing     -> pure ()
  645     Just broker -> broadcastListsSnapshot broker tabsH (cdPaths deps)

  647 -- | Build a 'TabCloseNotifier' from the shared cursor store + reply
  648 -- registry. When a tab is closed, every conversation whose cursor points
  649 -- at the closed tab's 'TabRef' is notified via the reply fan-out (so the
  650 -- message lands on the channel handle the conversation last used), and the
  651 -- cursor is cleared so the next message creates a fresh tab. For
  652 -- 'BoundHarness' tabs there are no channel subscriptions, so this is a
  653 -- no-op. Used by the slash-command registry's @\/tab close@ and the REST
  654 -- @POST \/api\/tabs\/:index\/close@ path.
  655 mkTabCloseNotifier :: CursorStore -> ReplyRegistry -> TabCloseNotifier
  656 mkTabCloseNotifier cursors replies ref = case ref of
  657   BoundSession sid -> do
  658     replyFanout replies sid (msg sid)
  659     cursorClearAll cursors ref
  660   BoundHarness _ -> pure ()
  661   where
  662     msg sid = "tab closed (session " <> sessionIdText sid <> "); a new tab will be created on your next message"

  664 -- | Handle a parsed 'TabSlashCommand' over a channel (mutates the
  665 -- TabsHandle, replies via chSend). Mirrors Seal.Channel.Cli.handleTabCommand.
  666 handleTabCommand :: ChannelHandle -> TabsHandle -> TabSlashCommand -> IO ()
  667 handleTabCommand h tabsH = \case
  668   TabListCmd -> do
  669     tl <- snapshotTabs tabsH
  670     if tabCount tl == 0
  671       then chSend h "no tabs"
  672       else mapM_ (chSend h . renderCurrentTab) (tlTabs tl)
  673   TabNewCmd _mKind -> do
  674     r <- insertTabH tabsH (BoundSession placeholderSid) KindAi Nothing
  675     case r of
  676       Left e  -> chSend h ("tab new failed: " <> e)
  677       Right i -> chSend h ("tab " <> T.singleton (tabIndexToChar i) <> " created")
  678   TabCloseCmd idx force -> do
  679     r <- removeTabH tabsH idx
  680     case r of
  681       Left e  -> chSend h (if force == Force then "force close: " <> e else "close failed: " <> e)
  682       Right _ -> chSend h ("tab " <> T.singleton (tabIndexToChar idx) <> " closed")
  683   TabFocusCmd idx -> do
  684     r <- focusTabH tabsH idx
  685     case r of
  686       Left e  -> chSend h ("focus failed: " <> e)
  687       Right _ -> chSend h ("focused tab " <> T.singleton (tabIndexToChar idx))
  688   TabResumeCmd sid -> do
  689     r <- insertTabH tabsH (BoundSession sid) KindAi Nothing
  690     case r of
  691       Left e  -> chSend h ("resume failed: " <> e)
  692       Right i -> chSend h ("tab " <> T.singleton (tabIndexToChar i) <> " resumed")
  693   TabRenameCmd idx name -> do
  694     r <- renameTabH tabsH idx name
  695     case r of
  696       Left e  -> chSend h ("rename failed: " <> e)
  697       Right _ -> chSend h ("tab " <> T.singleton (tabIndexToChar idx) <> " renamed to " <> name)
  698   where
  699     placeholderSid = case mkSessionId "tab-session" of
  700       Right s -> s
  701       Left _  -> error "placeholder session id"

  703 -- | Render one tab as a single line: @<index>  <kind>  [label]@.
  704 renderCurrentTab :: Tab -> Text
  705 renderCurrentTab t =
  706   T.singleton (tabIndexToChar (tIndex t)) <> "  " <> T.pack (show (tKind t))
  707     <> maybe "" ("  " <>) (tLabel t)

  731 -- | The shared turn body. 'askSid' is the 'SessionId' used to key the
  732 -- 'ccPrompt' ask/reply slot: for a normal turn it is the session's own sid
  733 -- (the conversation's active session); for a @/bg@ turn it is the
  734 -- /originating conversation's/ sid (NOT the fresh bg session's) so the
  735 -- channel loop's per-session 'deliverNextAnswer' short-circuit consumes the
  736 -- next inbound message as the confirmation answer — producing a modal
  737 -- "answer the pending question before resuming normal turns" state scoped
  738 -- to that conversation. The turn itself still runs on 'smId meta' (the bg
  739 -- session): transcript, 'aeSession', and the approval cache stay scoped to
  740 -- the bg session; only the ask-delivery key moves to the conversation.
  741 runTurnOnSession
  742   :: ChannelDeps -> ChannelHandle -> AskReplyStore
  743   -> Maybe (ChannelHandle -> AskReplyStore -> SessionId -> ChannelCaps)
  744   -> SessionId -> SessionMeta -> Maybe MessageSource -> Text -> IO ()
  745 runTurnOnSession deps h askReply mkCaps askSid meta mSrc t = do
  746   let td = mkChannelTurnDeps deps
  747       handleCaps = case mkCaps of
  748         Nothing  -> mkHandleCaps h askReply askSid
  749         Just f   -> f h askReply askSid
  750       adapter = mkChannelTurnAdapter deps td h handleCaps
  751   _ <- runSessionTurn td adapter meta mSrc t
  752   pure ()

  754 -- | Build the @/bg@ 'BgRunner' for an inbox-driven channel. The runner mints
  755 -- a fresh persisted session from the config defaults (channel label
  756 -- @"bg"@), then forks a turn against the invoking 'ChannelHandle'. The
  757 -- confirmation ask is keyed to the /originating conversation's/ active
  758 -- session id (read from 'bgConvSid', which the loop updates each turn) —
  759 -- NOT the fresh bg session's sid — so the channel loop's per-session
  760 -- 'deliverNextAnswer' short-circuit consumes the next inbound message as
  761 -- the confirmation answer (a modal "answer the pending question before
  762 -- resuming normal turns" state scoped to that conversation). The turn
  763 -- itself runs on the fresh bg session (transcript + 'aeSession' + approval
  764 -- cache stay scoped to it); only the ask-delivery key moves to the
  765 -- conversation. The assistant reply is delivered via the handle's
  766 -- @chSend@. No tab or cursor state is mutated.
  767 --
  768 -- After persisting the session, a @lists@ snapshot is broadcast (via
  769 -- 'broadcastTabs') so the web frontend's 'useListsStream' learns about the
  770 -- new session immediately — it surfaces in @recentSessions@ (it's a real,
  771 -- persisted, one-shot session, just not tabbed). At this point the
  772 -- transcript is empty so the row shows the agent name as a placeholder;
  773 -- the @runTurnOnSession@ path's @aeOnUserMessage@ hook (wired in
  774 -- 'runTurnOnSession' when @shouldAutoTab@ is False) re-broadcasts a
  775 -- @lists@ snapshot as soon as the user message is durable on disk, so
  776 -- the snippet (the first user message) populates the session name
  777 -- before the LLM responds. Without the pre-turn push the frontend only
  778 -- discovers the session on a hard refresh. No-op when 'cdBroker' is
  779 -- 'Nothing' (standalone Telegram/Signal without @seal serve@).
  780 mkBgRunner :: ChannelDeps -> ChannelHandle -> AskReplyStore -> IORef SessionId -> TabsHandle -> BgRunner
  781 mkBgRunner deps h askReply bgConvSid tabsH = BgRunner $ \prompt -> do
  782   convSid <- readIORef bgConvSid
  783   cfg <- cdConfig deps
  784   (mAgent, mProv, mModel) <- resolveDefaultAgent (bAgentDefs (cdBackends deps)) cfg
  785   let (cfgProv, cfgModel) = defaultSessionSelection cfg
  786       provider = fromMaybe cfgProv mProv
  787       model    = fromMaybe cfgModel mModel
  788   meta <- newSessionMeta (cdPaths deps) provider model "bg" mAgent
  789   saveSessionMeta (cdPaths deps) meta
  790   broadcastTabs deps tabsH
  791   void (forkIO (runTurnOnSession deps h askReply Nothing convSid meta Nothing prompt))
