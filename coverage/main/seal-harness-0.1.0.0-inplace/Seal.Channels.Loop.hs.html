    3 -- channels (and any future inbox-driven channel). The loop pulls
    4 -- @(MessageSource, body)@ from 'chReceive', classifies via
    5 -- 'Seal.Routing.Route' (Layer-1 terse grammar + /tab commands BEFORE the
    6 -- /-command registry), dispatches slash commands via a 'ChannelCaps'
    7 -- adapter over the 'ChannelHandle', and routes plain messages to the
    8 -- supplied 'plainHandler' (which runs 'runTurn' with 'aeMessageSource' =
    9 -- @Just ms@). Terminates when 'chReceive' returns EOF.
   10 --
   11 -- The 'ChannelDeps' record bundles everything a channel turn needs to have
   12 -- parity with the web and CLI paths: the full ISA registry (including
   13 -- Untrusted execution opcodes, web fetch/search, harness ops, and
   14 -- AGENT_START), the WS broker for live transcript updates, and the harness
   15 -- + tmux + HTTP manager deps. This ensures every channel gets identical
   16 -- transcript logging and tool-call infrastructure.
   17 --
   18 -- == Tab-centric session model
   19 --
   20 -- Each conversation (a Telegram chat, a Signal conversation) has its own
   21 -- cursor into the shared tab list ('CursorStore'). On first message from
   22 -- a conversation, a new tab + session is created and the cursor is set.
   23 -- Subsequent messages resolve the session via the cursor → tab → SessionId
   24 -- path, NOT via a shared active-session ref. This means @/tab focus N@
   25 -- on one Telegram conversation only affects that conversation — other
   26 -- conversations keep their own cursor. The web frontend has no cursor; it
   27 -- sends to a specific session by id (the tab the user clicked).
   28 --
   29 -- Replies fan out to all channels focused on the session via the
   30 -- 'ReplyRegistry' — so a web-originated turn on a Telegram-session tab
   31 -- also delivers the reply to Telegram. A per-session write lock
   32 -- ('SessionLocks') serializes concurrent turns on the same session to
   33 -- prevent transcript corruption.

  237 -- | Build the channel 'TurnAdapter' for a given 'ChannelHandle' +
  238 -- 'ChannelCaps'. The channel adapter:
  239 -- * @taPreTurn@ — 'replySubscribe's the channel handle to the session's
  240 --   replies (so the post-turn fan-out delivers the assistant response to
  241 --   this channel) + 'replyFanoutMessage' mirrors the user's message to
  242 --   every OTHER subscribed channel (cross-channel mirroring, the handle's
  243 --   label).
  244 -- * @taChannelLabel@ — the session's 'smChannel' (an inbox session is
  245 --   always created on the channel its messages arrive on).
  246 -- * @taOnStop@ — 'Just' the reply fan-out so subscribed channels receive
  247 --   the final reply.
  248 -- * @taOnUserMessage@ — for /bg turns, 'Just' a 'broadcastTabs' refresh so
  249 --   the sidebar shows the session name as soon as the user message is
  250 --   durable; 'Nothing' for normal turns (the post-turn 'taPostTurn'
  251 --   refresh covers them).
  252 -- * @taPostTurn@ — 'broadcastTabs' so the sidebar reflects the new tab +
  253 --   the first-message snippet. Runs for both auto-tab and /bg paths.
  254 -- * @taStartWiring@ — the engine-owned 'TurnEngine.buildStartWiring' (W4
  255 --   collapsed the per-surface builders into this single one).
  256 mkChannelTurnAdapter
  257   :: ChannelDeps -> TurnDeps -> ChannelHandle -> ChannelCaps
  258   -> IORef (Maybe StreamProgress)
  259   -> TurnAdapter
  260 mkChannelTurnAdapter deps td h caps spRef = TurnAdapter
  261   { taCaps          = caps
  262   , taPreTurn       = \sid _meta t -> do
  263       _ <- replySubscribe (cdReplies deps) h sid
  264       replyFanoutMessage (cdReplies deps) sid (chLabel h) t
  265   , taChannelLabel  = smChannel
  266   , taOnStop        = Just . replyFanout (cdReplies deps)
  267   , taOnToolCall    = Just (toolCallHook deps h (cdReplies deps) (chLabel h) spRef)
  268   , taOnTextDelta   = Nothing
  269   , taOnUserMessage = \meta -> if shouldAutoTab meta
  270                                  then Nothing
  271                                  else Just (broadcastTabs deps (cdTabs deps))
  272   , taPostTurn      = \_ _ -> broadcastTabs deps (cdTabs deps)
  273   , taStartWiring   = \sessionBackends sid appEnv eCfg operatorCeiling meta ->
  274       TurnEngine.buildStartWiring td sessionBackends sid appEnv eCfg operatorCeiling (smChannel meta)
  275   }

  277 -- | The per-turn tool-call hook. Lazily creates a 'StreamProgress' on the
  278 -- first tool call of the turn, then reuses it for all subsequent calls so
  279 -- the tool-progress bubble is edited (not re-sent). The 'StreamProgress'
  280 -- lives in the 'IORef' supplied by 'mkChannelTurnAdapter', which is
  281 -- per-turn (the adapter is created fresh for each turn in
  282 -- 'runTurnOnSession').
  283 --
  284 -- Calls 'segmentBreak' (finalize any in-progress text) followed by
  285 -- 'onToolCall' (send/edit the tool-progress bubble). When streaming is
  286 -- disabled, 'newStreamProgress' still creates the state but 'onToolCall'
  287 -- and 'segmentBreak' are no-ops (they check 'spcEnabled' internally).
  288 --
  289 -- The hook checks 'replyIsSubscribed' before sending: if the channel has
  290 -- run @/tab focus@ to switch to a different session mid-turn, the handle
  291 -- is no longer subscribed to this session and the tool-progress bubble is
  292 -- suppressed. This ensures a chat channel only shows tool updates for the
  293 -- tab it's currently focused on. IO.
  294 toolCallHook
  295   :: ChannelDeps -> ChannelHandle -> ReplyRegistry -> Text
  296   -> IORef (Maybe StreamProgress)
  297   -> SessionId -> OpName -> Value -> IO ()
  298 toolCallHook deps h replies label spRef sid opName input = do
  299   -- Only send tool progress if this channel is still subscribed to the
  300   -- session (i.e. the user hasn't /tab focus'd away to a different session).
  301   subscribed <- replyIsSubscribed replies label sid
  302   when subscribed $ do
  303     cfg <- cdConfig deps
  304     let spCfg = chatStreamingConfig cfg
  305     mSp <- readIORef spRef
  306     sp <- case mSp of
  307       Just existing -> pure existing
  308       Nothing -> do
  309         sp' <- newStreamProgress spCfg h secretOpcodes
  310         writeIORef spRef (Just sp')
  311         pure sp'
  312     segmentBreak sp
  313     onToolCall sp opName (TE.decodeUtf8 (BL.toStrict (A.encode input)))

  372 -- | Build the channel's slash-command registry from a supplied base
  373 -- 'Registry' plus the channel-specific @bg@, @call@, @skill@, and @model@
  374 -- specs.
  375 --
  376 -- The channel-appended specs bind to the channel's per-session
  377 -- 'channelCallDispatcher' (which reads the conversation's cursor-resolved
  378 -- sid). Under @seal serve@, the supplied @registry@ is the WEB gateway's
  379 -- registry, whose @skill@ and @call@ specs bind to 'webCallDispatcher'
  380 -- (which reads the process-global @srActive@ ref). Without shadowing those
  381 -- out, a @/skill load@ issued from Telegram dispatches via the FIRST
  382 -- matching spec — the web one — and records the SKILL_LOAD entry on
  383 -- whatever session @srActive@ points at, NOT the Telegram conversation's
  384 -- session. The same hazard applies to @/model use@ (the core spec writes
  385 -- @srActive@'s session.json, not the conversation's). The channel-dispatcher
  386 --   versions must win, so drop any incoming spec whose primary name collides
  387 --   with a channel-appended spec before appending them. 'lookupSpec' returns
  388 --   the first match, so the appended channel specs then resolve correctly.
  389 --
  390 -- The @model@ spec is built from the channel's 'ProviderRuntime' + 'SealPaths'
  391 -- + broker (passed explicitly rather than reading the whole 'ChannelDeps' so
  392 -- the registry builder stays decoupled from the full deps record — the
  393 -- pure-registry tests don't need to construct a full 'ChannelDeps').

  396   -> SkillBackend -> BgRunner -> CallDispatcher

  414 -- | The inbox-driven loop. Spawns the channel via the supplied bracket,
  415 -- pulls @(MessageSource, body)@ from 'chReceive', classifies via
  416 -- 'Seal.Routing.Route', and dispatches. Each conversation resolves its
  417 -- session via the cursor store (not a shared active-session ref). On
  418 -- first message from a conversation, a new tab + session is created.
  419 --
  420 -- The optional 'mkCaps' factory overrides the default 'mkHandleCaps'
  421 -- (e.g. Telegram's inline-keyboard 'ccPrompt'). 'Nothing' = use
  422 -- 'mkHandleCaps' (Signal + the generic numbered list).
  423 --
  424 -- The optional 'onCallback' hook is called before
  425 -- 'deliverNextAnswerResolved' — Telegram uses it to route callback_query
  426 -- button taps by 'AskId' (by-id delivery, NOT FIFO). 'Nothing' = no
  427 -- callback support (the body goes straight to 'deliverNextAnswerResolved').
  428 runChannelLoop
  429   :: (Channel c)
  430   => ChannelDeps
  431   -> ((c -> IO ()) -> IO ())
  432   -> (ChannelHandle -> SessionMeta -> Maybe MessageSource -> Text -> IO ())
  433   -> Registry
  434   -> PreprocessChain
  435   -> AskReplyStore
  436   -> TabsHandle
  437   -> Maybe (ChannelHandle -> AskReplyStore -> SessionId -> ChannelCaps)
  438   -> Maybe (ChannelHandle -> SessionId -> Text -> IO Bool)
  439   -> IO ()
  440 runChannelLoop deps withChannel plainHandler registry chain askReply tabsH mkCaps onCallback =
  441   withChannel $ \ch -> do
  442     let h = toHandle ch
  443     -- A mutable cell holding the originating conversation's active session
  444     -- id, updated each turn before any slash command is dispatched. The
  445     -- /bg runner reads it to key the confirmation ask to the conversation
  446     -- (not the fresh bg session), so the loop's deliverNextAnswer
  447     -- short-circuit consumes the next inbound message as the answer. The
  448     -- initial bottom is never read: the loop writes the real sid before
  449     -- any /bg dispatch.
  450     bgConvSid <- newIORef (error "bgConvSid: set before first dispatch" :: SessionId)
  451     let td = mkChannelTurnDeps deps
  452         bgRunner = mkBgRunner deps h askReply bgConvSid tabsH
  453         -- A factory that builds a CallDispatcher for an explicit sid
  454         -- (used by handleNewSession to dispatch SETUP_REPO into the new
  455         -- session). The new sid isn't in bgConvSid yet (cursor migrate
  456         -- happens inside handleNewSession), so we use the explicit-sid
  457         -- variant instead of channelCallDispatcher.
  458         dispatcherFactory = channelCallDispatcherForSid deps td h askReply
  459         callDispatcher = channelCallDispatcher deps td h askReply bgConvSid
  460         registryWithBg = buildChannelRegistry
  461           (cdProvider deps) (cdPaths deps) (cdBroker deps)
  462           (bSkills (cdBackends deps)) bgRunner callDispatcher bgConvSid registry
  463     loop h registryWithBg bgConvSid dispatcherFactory
  464   where
  465     loop h reg bgConvSid dispatcherFactory = do
  466       (mSrc, body) <- chReceive h
  467       case mSrc of
  468         Nothing -> pure ()  -- EOF
  469         Just ms -> do
  470           let key = convKey ms
  471               bgRoute = isBgSlash body
  472           -- Resolve the conversation's session (create if first message).
  473           -- For a /bg command, take the headless path: the conversation needs
  474           -- an anchor session (its sid keys the bg runner's confirmation ask
  475           -- via bgConvSid below) but must NOT get a tab, since no turn ever
  476           -- runs on this session — a tab would surface as an empty
  477           -- conversation in the web sidebar. The bg turn itself runs on a
  478           -- separate, fresh bg session minted by mkBgRunner.
  479           mCursor <- cursorLookup (cdCursors deps) key
  480           meta <- case mCursor of
  481             Just tabRef -> do
  482               mMeta <- resolveTabSession deps tabRef
  483               case mMeta of
  484                 Just m  -> pure m
  485                 Nothing
  486                   | bgRoute  -> createConversationSessionHeadless deps key (msChannelKind ms)
  487                   | otherwise -> createConversationSession deps h key (msChannelKind ms) tabsH
  488             Nothing
  489               | bgRoute  -> createConversationSessionHeadless deps key (msChannelKind ms)
  490               | otherwise -> createConversationSession deps h key (msChannelKind ms) tabsH
  491           let sid = smId meta
  492           -- Record the conversation's active session so the /bg runner
  493           -- (dispatched below if this turn is a /bg) keys its confirmation
  494           -- ask to this sid. Updated every turn, before any slash-command
  495           -- dispatch.
  496           writeIORef bgConvSid sid
  497           -- For channels with callback support (Telegram), try the
  498           -- onCallback hook first (by-id delivery for button taps). If it
  499           -- returns True, the body was a callback + delivered; continue
  500           -- the loop. Otherwise, fall through to deliverNextAnswerResolved.
  501           mCallbackHandled <- case onCallback of
  502             Nothing -> pure False
  503             Just cb -> cb h sid body
  504           delivered <-
  505             if mCallbackHandled
  506               then pure True
  507               else snd <$> deliverNextAnswerResolved askReply sid body
  508           if delivered
  509             then loop h reg bgConvSid dispatcherFactory
  510             else do
  511               let handleCaps = case mkCaps of
  512                     Nothing -> mkHandleCaps h askReply sid
  513                     Just f  -> f h askReply sid
  514               case Route.route body of
  515                 Right (Route.Focus idx) -> do
  516                   _ <- focusTabH tabsH idx
  517                   tl <- snapshotTabs tabsH
  518                   case lookupTabByIndex tl idx of
  519                     Just tab -> cursorSet (cdCursors deps) key (tRef tab)
  520                     Nothing -> pure ()
  521                   chSend h ("focused tab " <> T.singleton (tabIndexToChar idx))
  522                   loop h reg bgConvSid dispatcherFactory
  523                 Right (Route.Inject idx payload) -> do
  524                   _ <- focusTabH tabsH idx
  525                   void (forkIO (plainHandler h meta (Just ms) payload))
  526                   loop h reg bgConvSid dispatcherFactory
  527                 Right (Route.TabCommand tsc) -> do
  528                   _ <- handleTabCommand h tabsH tsc
  529                   loop h reg bgConvSid dispatcherFactory
  530                 Right Route.CurrentTab -> do
  531                   tl <- snapshotTabs tabsH
  532                   case mCursor >>= lookupByRef tl of
  533                     Just t  -> chSend h (renderCurrentTab t)
  534                     Nothing -> chSend h "no current tab"
  535                   loop h reg bgConvSid dispatcherFactory
  536                 Right (Route.NewSession rawArgs) -> do
  537                   let newArgs = parseNewArgs rawArgs
  538                   _ <- handleNewSession deps h tabsH (msChannelKind ms) meta newArgs (Just dispatcherFactory)
  539                   loop h reg bgConvSid dispatcherFactory
  540                 Right (Route.SlashCommand _) -> do
  541                  -- Intercept /tab focus <N> before the registry: the
  542                  -- registry's focusCmd only validates the index (it has
  543                  -- no access to the cursor store or conversation key), so
  544                  -- the cursor would not be updated and the next plain
  545                  -- message would still route to the old session. Handle
  546                  -- it inline with cursor update + reply subscribe + last
  547                  -- reply delivery, matching the /N terse-grammar path.
  548                  case parseTabFocus body of
  549                    Just idx -> do
  550                      handleTabFocus deps h tabsH key idx
  551                      loop h reg bgConvSid dispatcherFactory
  552                    Nothing -> do
  553                      d <- ingest reg chain (RawInbound body)
  554                      case d of
  555                        DispatchAction a -> do
  556                          eResult <- withExceptionLogging (cdLogger deps) Nothing "slash command" $
  557                            runCommandAction a handleCaps
  558                          case eResult of
  559                            Left errMsg -> chSend h errMsg
  560                            Right mFollowUp -> case mFollowUp of
  561                              Just t  -> void (forkIO (plainHandler h meta (Just ms) t))
  562                              Nothing -> pure ()
  563                          loop h reg bgConvSid dispatcherFactory
  564                        ShowText t       -> chSend h t >> loop h reg bgConvSid dispatcherFactory
  565                        PlainMessage t   -> void (forkIO (plainHandler h meta (Just ms) t)) >> loop h reg bgConvSid dispatcherFactory
  566                        Rejected msg     -> chSend h msg >> loop h reg bgConvSid dispatcherFactory
  567                 Right (Route.Plain t) -> do
  568                   void (forkIO (plainHandler h meta (Just ms) t))
  569                   loop h reg bgConvSid dispatcherFactory
  570                 Left (Route.ParseError e) -> do
  571                   chSend h e
  572                   loop h reg bgConvSid dispatcherFactory

  574 -- | Build the per-turn 'ChannelCaps' for a channel handle.
  575 mkHandleCaps :: ChannelHandle -> AskReplyStore -> SessionId -> ChannelCaps
  576 mkHandleCaps h askReply sid = def
  577   { ccSend         = chSend h
  578   , ccShowHuman    = chSend h
  579   , ccPrompt       = \(AskPrompt q opts) -> do
  580       chSend h (formatQuestionWithOptions q opts)
  581       outcome <- askHumanWithOptions askReply sid q opts (const (pure ()))
  582       pure (fromRight "" outcome)
  583   , ccPromptSecret = fmap (fromRight "") . chPromptSecret h
  584   , ccStreaming    = chStreaming h
  585   }

  591     go [] = Nothing
  592     go (t:rest) | tIndex t == idx = Just t
  593                 | otherwise       = go rest

  595 -- | Resolve a 'TabRef' to its session meta by loading from disk.
  596 -- 'Nothing' if the tab was closed or the session.json is missing.
  597 resolveTabSession :: ChannelDeps -> TabRef -> IO (Maybe SessionMeta)

  603       then pure Nothing

  605   BoundHarness _   -> pure Nothing

  607 -- | Handle @\/new@ on an inbox channel: mint a fresh session, rebind the
  608 -- conversation's current tab (if any) to the new sid, migrate every OTHER
  609 -- conversation cursor pointing at the old ref to the new ref, and send the
  610 -- confirmation line. The old session is kept on disk (still in
  611 -- @/session list@).
  612 --
  613 -- When 'NewArgs' overrides are given (@-p@\/@-m@), the new session uses
  614 -- the overrides instead of copying the old session's provider/model.
  615 -- When @-r@\/@--repo@ is given and a 'CallDispatcher' factory is supplied,
  616 -- 'SETUP_REPO' is dispatched into the new session (same as the web
  617 -- frontend's "Set up repo" field). When @-r@ is given but no factory is
  618 -- available, a warning is sent.
  619 --
  620 -- Mirrors the CLI's @\/new@ path but lives at the loop level because the
  621 -- conversation key + cursor aren't available to a registry CommandAction
  622 -- (architect review issue C). The fresh @meta@ is NOT used to run a turn —
  623 -- the next inbound message's cursor lookup resolves to the new session
  624 -- automatically (the cursor migrate ensures that).
  625 --
  626 -- The @dispatcherFactory@ is @'Just' (sid -> 'CallDispatcher')@ when the
  627 -- loop has a dispatcher available (it always does under @seal serve@ and
  628 -- standalone @seal signal@\/@seal telegram@). 'Nothing' only in tests
  629 -- that don't wire the dispatcher.
  630 handleNewSession
  631   :: ChannelDeps -> ChannelHandle -> TabsHandle
  632   -> ChannelKind -> SessionMeta -> NewArgs
  633   -> Maybe (SessionId -> CallDispatcher) -> IO ()
  634 handleNewSession deps h tabsH kind oldMeta args mDispatcherFactory = do
  635   -- Apply -p/-m overrides (falling back to the old session's values so
  636   -- mid-session /model use changes survive /new). The agent is resolved
  637   -- from config defaults (NOT inherited from the old session) — matching
  638   -- the web frontend's "New Tab" flow which starts unbound and lets the
  639   -- first turn's autoBindRepoAgent + resolveSystemPrompt resolve the
  640   -- default. Inheriting the old session's agent would carry forward a
  641   -- repo-specific binding to a session that has no repo.
  642   let channelLabel = channelKindToText kind
  643       oldSid = smId oldMeta
  644       oldRef = BoundSession oldSid
  645       provider = fromMaybe (smProvider oldMeta) (naProvider args)
  646       model = fromMaybe (smModel oldMeta) (naModel args)
  647   -- Resolve the default agent from config (same as createConversationSession
  648   -- and the web frontend's handleTabNew, which both start with no agent
  649   -- binding and let the first turn's autoBindRepoAgent resolve it).
  650   cfg <- cdConfig deps
  651   (mAgent, _mProv, _mModel) <- resolveDefaultAgent (bAgentDefs (cdBackends deps)) cfg
  652   newMeta <- newSessionMeta (cdPaths deps) provider model channelLabel mAgent
  653   saveSessionMeta (cdPaths deps) newMeta
  654   -- Rebind the tab (if any) bound to the old sid to the new sid.
  655   snap <- snapshotTabs tabsH
  656   case [ t | t <- tlTabs snap, tRef t == oldRef ] of
  657     []       -> pure ()  -- no tab bound to old sid; cursor-only swap below
  658     (tab : _) -> rebindTabH tabsH (tIndex tab) (BoundSession (smId newMeta)) >>= \case
  659       Left e  -> chSend h ("warning: /new tab rebind failed: " <> e)
  660       Right _ -> broadcastTabs deps tabsH
  661   -- Migrate every conversation cursor pointing at the old ref to the new
  662   -- ref (includes THIS conversation's cursor). Per the user's model: a tab
  663   -- has one session at a time; all channels focused on it follow the
  664   -- rebind to the new session.
  665   _count <- cursorMigrateAll (cdCursors deps) oldRef (BoundSession (smId newMeta))
  666   -- Migrate reply subscriptions from the old session to the new one so
  667   -- future fan-outs (including tab-close notifications) reach attached
  668   -- channels under the new session id.
  669   _n <- replyMigrateAll (cdReplies deps) oldSid (smId newMeta)
  670   -- When -r/--repo is given, dispatch SETUP_REPO into the new session
  671   -- (same as the web frontend's "Set up repo" field). The dispatcher
  672   -- factory creates a CallDispatcher bound to the new session's sid.
  673   for_ (naRepo args) $ \repoVal -> do
  674     repoUrl <- resolveRepoUrl (cdRepoReg deps) repoVal
  675     case mDispatcherFactory of
  676       Just mkDispatcher -> do
  677         let dispatcher = mkDispatcher (smId newMeta)
  678         case validateRepoUrl repoUrl of
  679           Left err -> chSend h ("repo setup failed: invalid url: " <> err)
  680           Right cleanUrl -> do
  681             eRes <- dispatcher (OpName "SETUP_REPO") (object ["url" .= cleanUrl])
  682             case eRes of
  683               Left dErr -> chSend h ("repo setup failed: " <> T.pack (show dErr))
  684               Right _   -> pure ()
  685       Nothing -> chSend h ("warning: repo setup not available on this channel; "
  686                          <> "use the web frontend or /repo to clone manually into "
  687                          <> "session " <> sessionIdText (smId newMeta))
  688   chSend h
  689     ("new session " <> sessionIdText (smId newMeta)
  690        <> " (" <> smProvider newMeta <> "/" <> smModel newMeta <> ")"
  691        <> " — prior session " <> sessionIdText oldSid <> " kept in /session list")

  693 -- | Create a new session + tab for a conversation that has no cursor yet.
  694 -- Mints a 'SessionMeta' from config defaults, persists it, inserts a tab
  695 -- into the shared 'TabsHandle', and sets the conversation's cursor.
  696 createConversationSession
  697   :: ChannelDeps -> ChannelHandle -> (Text, Text) -> ChannelKind
  698   -> TabsHandle -> IO SessionMeta
  699 createConversationSession deps _h key kind tabsH = do
  700   cfg <- cdConfig deps
  701   (mAgent, mProv, mModel) <- resolveDefaultAgent (bAgentDefs (cdBackends deps)) cfg
  702   let (cfgProv, cfgModel) = defaultSessionSelection cfg
  703       provider = fromMaybe cfgProv mProv
  704       model    = fromMaybe cfgModel mModel
  705       channelLabel = channelKindToText kind
  706   meta <- newSessionMeta (cdPaths deps) provider model channelLabel mAgent
  707   saveSessionMeta (cdPaths deps) meta
  708   -- Bind the conversation's cursor to this session unconditionally. The
  709   -- cursor is what the loop's next-turn lookup (Loop.hs:278) uses to
  710   -- resolve the conversation's session; if it isn't set, the next message
  711   -- mints a brand-new session and orphans this one. Earlier this lived
  712   -- inside the 'Right _' branch below, so a full tab list (Left _) silently
  713   -- skipped cursor-binding — every subsequent turn from the conversation
  714   -- would mint a fresh session, never reusing this one.
  715   cursorSet (cdCursors deps) key (BoundSession (smId meta))
  716   r <- insertTabH tabsH (BoundSession (smId meta)) KindAi Nothing
  717   case r of
  718     Left _ -> pure ()  -- tab list full; session still works without a tab
  719     Right _ ->
  720       -- Push the new tab to any WS subscribers (the web frontend sidebar)
  721       -- so a channel-created tab surfaces immediately. No-op when cdBroker
  722       -- is Nothing (standalone signal/telegram without serve).
  723       broadcastTabs deps tabsH
  724   pure meta

  726 -- | Create a new session for a conversation WITHOUT inserting a tab or
  727 -- broadcasting to the sidebar. Used by the @/bg@ path (see 'isBgSlash')
  728 -- where the conversation needs an anchor session (its sid keys the bg
  729 -- runner's confirmation ask via 'bgConvSid') but must NOT surface an empty
  730 -- tab in the web sidebar — the @/bg@ turn runs headless on a fresh bg
  731 -- session, so a tab bound to this conversation session would never receive
  732 -- a turn and would appear dead. The cursor is always set (unlike
  733 -- 'createConversationSession', there is no tab-list-full failure mode to
  734 -- skip it on), so subsequent non-bg messages resolve to this session.
  735 createConversationSessionHeadless
  736   :: ChannelDeps -> (Text, Text) -> ChannelKind -> IO SessionMeta
  737 createConversationSessionHeadless deps key kind = do
  738   cfg <- cdConfig deps
  739   (mAgent, mProv, mModel) <- resolveDefaultAgent (bAgentDefs (cdBackends deps)) cfg
  740   let (cfgProv, cfgModel) = defaultSessionSelection cfg
  741       provider = fromMaybe cfgProv mProv
  742       model    = fromMaybe cfgModel mModel
  743       channelLabel = channelKindToText kind
  744   meta <- newSessionMeta (cdPaths deps) provider model channelLabel mAgent
  745   saveSessionMeta (cdPaths deps) meta
  746   cursorSet (cdCursors deps) key (BoundSession (smId meta))
  747   pure meta

  749 -- | Does an inbound body route to a @/bg@ slash command? Layer-1 routing
  750 -- ('Seal.Routing.Route.route') sends any @\/<other>…@ to 'SlashCommand'; this
  751 -- checks the command name is @"bg"@ (case-insensitive, matching the terse
  752 -- grammar's single-token form @\/bg@ or @\/bg <prompt>@). Used by the loop to
  753 -- pick the headless session-creation path, so @/bg@ does not mint a spurious
  754 -- empty tab for the conversation while still anchoring the bg runner's
  755 -- confirmation-ask key on the conversation's sid.
  756 isBgSlash :: Text -> Bool
  757 isBgSlash body =
  758   case Route.route body of
  759     Right (Route.SlashCommand rest) ->
  760       let cmd = T.toCaseFold (T.takeWhile (/= ' ') rest)
  761       in cmd == "bg"
  762     _ -> False

  764 -- | Parse @\/tab focus \<N\>@ from the inbound body. Returns 'Just' the
  765 -- 'TabIndex' if the body is @\/tab focus \<N\>@ (case-insensitive, N is a
  766 -- single tab-index char 0-9a-z), 'Nothing' otherwise. Used by the loop to
  767 -- intercept @\/tab focus@ before the registry dispatch (the registry's
  768 -- 'focusCmd' has no access to the cursor store or conversation key).
  769 parseTabFocus :: Text -> Maybe TabIndex
  770 parseTabFocus body =
  771   case Route.route body of
  772     Right (Route.SlashCommand rest) ->
  773       let parts = T.words (T.toCaseFold rest)
  774       in case parts of
  775            ["tab", "focus", idxStr] -> case T.uncons idxStr of
  776              Just (c, _) -> either (const Nothing) Just (tabIndexFromChar c)
  777              Nothing     -> Nothing
  778            _ -> Nothing
  779     _ -> Nothing

  781 -- | Push the current tab-list snapshot to WS subscribers (the web frontend
  782 -- sidebar). No-op when 'cdBroker' is 'Nothing' (standalone channels without
  783 -- @seal serve@). Call after any channel-side tab mutation so the frontend
  784 -- reflects the change without waiting for a web-originated turn.
  785 broadcastTabs :: ChannelDeps -> TabsHandle -> IO ()
  786 broadcastTabs deps tabsH =
  787   case cdBroker deps of
  788     Nothing     -> pure ()
  789     Just broker -> broadcastListsSnapshot broker tabsH (cdPaths deps)

  791 -- | Build a 'TabCloseNotifier' from the shared cursor store + reply
  792 -- registry. When a tab is closed, every conversation whose cursor points
  793 -- at the closed tab's 'TabRef' is notified via the reply fan-out (so the
  794 -- message lands on the channel handle the conversation last used), and the
  795 -- cursor is cleared so the next message creates a fresh tab. For
  796 -- 'BoundHarness' tabs there are no channel subscriptions, so this is a
  797 -- no-op. Used by the slash-command registry's @\/tab close@ and the REST
  798 -- @POST \/api\/tabs\/:index\/close@ path.
  799 mkTabCloseNotifier :: CursorStore -> ReplyRegistry -> TabCloseNotifier
  800 mkTabCloseNotifier cursors replies ref = case ref of
  801   BoundSession sid -> do
  802     replyFanout replies sid (msg sid)
  803     cursorClearAll cursors ref
  804   BoundHarness _ -> pure ()
  805   where
  806     msg sid = "tab closed (session " <> sessionIdText sid <> "); a new tab will be created on your next message"

  808 -- | Handle @\/tab focus \<N\>@ on an inbox channel: validate the index,
  809 -- update the conversation's cursor to point at the focused tab's session,
  810 -- subscribe the channel handle to the focused session's replies (so future
  811 -- assistant replies from that session are fanned out to this channel), and
  812 -- send the last assistant reply from the focused session to the channel so
  813 -- the user sees the conversation context immediately. Sends a "focused tab N"
  814 -- confirmation, or "focus failed" on an out-of-range index.
  815 --
  816 -- This closes the gap between @\/N@ (the terse grammar, which already
  817 -- updated the cursor) and @\/tab focus \<N\>@ (which previously only
  818 -- validated the index without updating the cursor, so the next plain
  819 -- message still routed to the old session).
  820 handleTabFocus
  821   :: ChannelDeps -> ChannelHandle -> TabsHandle
  822  -> (Text, Text) -> TabIndex -> IO ()
  823 handleTabFocus deps h tabsH key idx = do
  824   r <- focusTabH tabsH idx
  825   case r of
  826     Left e  -> chSend h ("focus failed: " <> e)
  827     Right _ -> do
  828       tl <- snapshotTabs tabsH
  829       case lookupTabByIndex tl idx of
  830         Nothing -> chSend h "focus failed: tab not found"
  831         Just tab -> do
  832           -- Update the conversation's cursor to the focused tab's ref.
  833           cursorSet (cdCursors deps) key (tRef tab)
  834           -- Subscribe the channel handle to the focused session's replies
  835           -- so future assistant replies (from any surface) are fanned out
  836           -- to this channel.
  837           case tRef tab of
  838             BoundSession sid -> do
  839               _ <- replySubscribe (cdReplies deps) h sid
  840               -- Send the last assistant reply from the focused session to
  841               -- the channel so the user sees the conversation context.
  842               sendLastAssistantReply deps h sid
  843             BoundHarness _ -> pure ()
  844           chSend h ("focused tab " <> T.singleton (tabIndexToChar idx))

  846 -- | Read the session's @conversation.jsonl@ and send the last assistant
  847 -- message's text content to the channel. No-op if the file is missing or
  848 -- has no assistant messages. Mirrors 'Seal.Core.TurnEngine.fanoutLastReply'
  849 -- but sends directly to the channel handle instead of fanning out.
  850 sendLastAssistantReply :: ChannelDeps -> ChannelHandle -> SessionId -> IO ()
  851 sendLastAssistantReply deps h sid = do
  852   let convPath = sessionConversationPath (cdPaths deps) sid
  853   exists <- doesFileExist convPath
  854   if not exists
  855     then pure ()
  856     else do
  857       raw <- BL.readFile convPath
  858       let lines' = filter (not . BL.null) (BL.split 0x0a raw)
  859           msgs = mapMaybe A.decode lines' :: [Message]
  860       for_ (lastAssistantText msgs) (chSend h)

  862 -- | Extract the concatenated text content of the last 'Assistant' message.
  863 lastAssistantText :: [Message] -> Maybe Text
  864 lastAssistantText msgs =
  865   case reverse (filter (\m -> msgRole m == Assistant) msgs) of
  866     (m : _) -> case [t | CbText t <- msgContent m] of
  867       (t : _) -> Just t
  868       []      -> Nothing
  869     []      -> Nothing

  871 -- | Handle a parsed 'TabSlashCommand' over a channel (mutates the
  872 -- TabsHandle, replies via chSend). Mirrors Seal.Channel.Cli.handleTabCommand.
  873 handleTabCommand :: ChannelHandle -> TabsHandle -> TabSlashCommand -> IO ()
  874 handleTabCommand h tabsH = \case
  875   TabListCmd -> do
  876     tl <- snapshotTabs tabsH
  877     if tabCount tl == 0
  878       then chSend h "no tabs"
  879       else mapM_ (chSend h . renderCurrentTab) (tlTabs tl)
  880   TabNewCmd _mKind -> do
  881     r <- insertTabH tabsH (BoundSession placeholderSid) KindAi Nothing
  882     case r of
  883       Left e  -> chSend h ("tab new failed: " <> e)
  884       Right i -> chSend h ("tab " <> T.singleton (tabIndexToChar i) <> " created")
  885   TabCloseCmd idx force -> do
  886     r <- removeTabH tabsH idx
  887     case r of
  888       Left e  -> chSend h (if force == Force then "force close: " <> e else "close failed: " <> e)
  889       Right _ -> chSend h ("tab " <> T.singleton (tabIndexToChar idx) <> " closed")
  890   TabFocusCmd idx -> do
  891     r <- focusTabH tabsH idx
  892     case r of
  893       Left e  -> chSend h ("focus failed: " <> e)
  894       Right _ -> chSend h ("focused tab " <> T.singleton (tabIndexToChar idx))
  895   TabResumeCmd sid -> do
  896     r <- insertTabH tabsH (BoundSession sid) KindAi Nothing
  897     case r of
  898       Left e  -> chSend h ("resume failed: " <> e)
  899       Right i -> chSend h ("tab " <> T.singleton (tabIndexToChar i) <> " resumed")
  900   TabRenameCmd idx name -> do
  901     r <- renameTabH tabsH idx name
  902     case r of
  903       Left e  -> chSend h ("rename failed: " <> e)
  904       Right _ -> chSend h ("tab " <> T.singleton (tabIndexToChar idx) <> " renamed to " <> name)
  905   where
  906     placeholderSid = case mkSessionId "tab-session" of
  907       Right s -> s
  908       Left _  -> error "placeholder session id"

  910 -- | Render one tab as a single line: @<index>  <kind>  [label]@.

  912 renderCurrentTab t =
  913   T.singleton (tabIndexToChar (tIndex t)) <> "  " <> T.pack (show (tKind t))
  914     <> maybe "" ("  " <>) (tLabel t)

  916 -- | Run one plain-text turn through the agent loop with the
  917 -- 'MessageSource' threaded into 'aeMessageSource'. Takes the resolved
  918 -- 'SessionMeta' (from the cursor → tab → SessionId path) rather than
  919 -- reading a shared active-session ref. Acquires the per-session write
  920 -- lock to prevent concurrent transcript corruption. After the turn, the
  921 -- reply is fanned out to all channels subscribed to this session.
  922 plainTurn

  924   -> SessionMeta -> Maybe MessageSource -> Text -> IO ()
  925 plainTurn deps h askReply meta =
  926   runTurnOnSession deps h askReply Nothing (smId meta) meta

  928 -- | Like 'plainTurn' but with an optional 'ChannelCaps' factory override
  929 -- (e.g. Telegram's 'mkTelegramHandleCaps' for inline-keyboard @ASK_HUMAN@).
  930 -- 'Nothing' uses the generic 'mkHandleCaps' (numbered-list rendering).
  931 plainTurnWithCaps
  932   :: ChannelDeps -> ChannelHandle -> AskReplyStore
  933   -> Maybe (ChannelHandle -> AskReplyStore -> SessionId -> ChannelCaps)
  934   -> SessionMeta -> Maybe MessageSource -> Text -> IO ()
  935 plainTurnWithCaps deps h askReply mkCaps meta =
  936   runTurnOnSession deps h askReply mkCaps (smId meta) meta

  938 -- | The shared turn body. 'askSid' is the 'SessionId' used to key the
  939 -- 'ccPrompt' ask/reply slot: for a normal turn it is the session's own sid
  940 -- (the conversation's active session); for a @/bg@ turn it is the
  941 -- /originating conversation's/ sid (NOT the fresh bg session's) so the
  942 -- channel loop's per-session 'deliverNextAnswer' short-circuit consumes the
  943 -- next inbound message as the confirmation answer — producing a modal
  944 -- "answer the pending question before resuming normal turns" state scoped
  945 -- to that conversation. The turn itself still runs on 'smId meta' (the bg
  946 -- session): transcript, 'aeSession', and the approval cache stay scoped to
  947 -- the bg session; only the ask-delivery key moves to the conversation.
  948 runTurnOnSession
  949   :: ChannelDeps -> ChannelHandle -> AskReplyStore
  950   -> Maybe (ChannelHandle -> AskReplyStore -> SessionId -> ChannelCaps)
  951   -> SessionId -> SessionMeta -> Maybe MessageSource -> Text -> IO ()
  952 runTurnOnSession deps h askReply mkCaps askSid meta mSrc t = do
  953   let td = mkChannelTurnDeps deps
  954       handleCaps = case mkCaps of
  955         Nothing  -> mkHandleCaps h askReply askSid
  956         Just f   -> f h askReply askSid
  957   spRef <- newIORef Nothing
  958   let adapter = mkChannelTurnAdapter deps td h handleCaps spRef
  959   _ <- runSessionTurn td adapter meta mSrc t
  960   pure ()

  962 -- | Build the @/bg@ 'BgRunner' for an inbox-driven channel. The runner mints
  963 -- a fresh persisted session from the config defaults (channel label
  964 -- @"bg"@), then forks a turn against the invoking 'ChannelHandle'. The
  965 -- confirmation ask is keyed to the /originating conversation's/ active
  966 -- session id (read from 'bgConvSid', which the loop updates each turn) —
  967 -- NOT the fresh bg session's sid — so the channel loop's per-session
  968 -- 'deliverNextAnswer' short-circuit consumes the next inbound message as
  969 -- the confirmation answer (a modal "answer the pending question before
  970 -- resuming normal turns" state scoped to that conversation). The turn
  971 -- itself runs on the fresh bg session (transcript + 'aeSession' + approval
  972 -- cache stay scoped to it); only the ask-delivery key moves to the
  973 -- conversation. The assistant reply is delivered via the handle's
  974 -- @chSend@. No tab or cursor state is mutated.
  975 --
  976 -- After persisting the session, a @lists@ snapshot is broadcast (via
  977 -- 'broadcastTabs') so the web frontend's 'useListsStream' learns about the
  978 -- new session immediately — it surfaces in @recentSessions@ (it's a real,
  979 -- persisted, one-shot session, just not tabbed). At this point the
  980 -- transcript is empty so the row shows the agent name as a placeholder;
  981 -- the @runTurnOnSession@ path's @aeOnUserMessage@ hook (wired in
  982 -- 'runTurnOnSession' when @shouldAutoTab@ is False) re-broadcasts a
  983 -- @lists@ snapshot as soon as the user message is durable on disk, so
  984 -- the snippet (the first user message) populates the session name
  985 -- before the LLM responds. Without the pre-turn push the frontend only
  986 -- discovers the session on a hard refresh. No-op when 'cdBroker' is
  987 -- 'Nothing' (standalone Telegram/Signal without @seal serve@).
  988 mkBgRunner :: ChannelDeps -> ChannelHandle -> AskReplyStore -> IORef SessionId -> TabsHandle -> BgRunner
  989 mkBgRunner deps h askReply bgConvSid tabsH = BgRunner $ \prompt -> do
  990   convSid <- readIORef bgConvSid
  991   cfg <- cdConfig deps
  992   (mAgent, mProv, mModel) <- resolveDefaultAgent (bAgentDefs (cdBackends deps)) cfg
  993   let (cfgProv, cfgModel) = defaultSessionSelection cfg
  994       provider = fromMaybe cfgProv mProv
  995       model    = fromMaybe cfgModel mModel
  996   meta <- newSessionMeta (cdPaths deps) provider model "bg" mAgent
  997   saveSessionMeta (cdPaths deps) meta
  998   broadcastTabs deps tabsH
  999   void (forkIO (runTurnOnSession deps h askReply Nothing convSid meta Nothing prompt))
