    2 -- | Extension-allowlisted MIME typing for in-browser image preview.
    3 --
    4 -- The file explorer's download endpoint serves every file as
    5 -- @application\/octet-stream@ with @Content-Disposition: attachment@ and
    6 -- @X-Content-Type-Options: nosniff@. That is deliberate: content from the
    7 -- agent's execution machine must never be rendered in the gateway's own
    8 -- origin, because that origin holds the operator's passkey session.
    9 --
   10 -- Image preview needs the opposite on exactly one endpoint variant: a
   11 -- correct @Content-Type@ and @nosniff@ (so the browser decodes the bytes
   12 -- as the type we declare, not as whatever they sniff). 'inlineMediaTypeFor'
   13 -- is the single gate deciding which files may take that path.
   14 --
   15 -- = Why an allowlist and not @mimeTypeFor@
   16 --
   17 -- A denylist of dangerous types is unbounded; a browser's renderer set is
   18 -- not. Only the handful of raster image formats below may be inlined.
   19 --
   20 -- = SVG: allowed, but only with a hardening CSP
   21 --
   22 -- @image\/svg+xml@ is a scriptable document format, so its inclusion is
   23 -- conditional. Two facts decide the design, both verified in a real browser
   24 -- (see 'svgHardeningCsp'):
   25 --
   26 -- * Inside an @<img>@ the browser decodes the file in a restricted mode —
   27 --   scripts never run and subresources never load. So rendering an SVG
   28 --   preview is safe *as a preview*.
   29 -- * The file stays fetchable at its own URL, and navigating there loads it
   30 --   as a DOCUMENT with scripting enabled, in this gateway's
   31 --   passkey-authenticated origin. A malicious @.svg@ fetched that way runs
   32 --   its script and can act as the operator.
   33 --
   34 -- The second fact is why 'inlineMediaTypeFor' returning an SVG is not
   35 -- enough on its own: the response also carries 'svgHardeningCsp', which
   36 -- neutralises the document-navigation path. A caller that serves SVG
   37 -- without that header has reintroduced the vulnerability.
   38 --
   39 -- = Why the extension, not the file's magic bytes
   40 --
   41 -- Sniffing content would mean reading the file before deciding how to serve
   42 -- it (an extra round trip, and on the remote arm an extra SSH command) and
   43 -- would make the served type depend on bytes the caller controls anyway. The
   44 -- extension is what the request is keyed on, and it is what the human sees
   45 -- in the file listing. A mis-named file yields a broken image — never a
   46 -- content-type escape, because 'nsniff' pins the type to our declaration.
   47 module Seal.Gateway.MediaType
   48   ( InlineMediaType (..)
   49   , inlineMediaTypeFor
   50   , svgHardeningCsp
   51   ) where
   52

   57 -- | An image type cleared for inline rendering, and the @Content-Type@
   58 -- header value it must be served with.
   59 --
   60 -- 'imtNeedsSvgCsp' distinguishes SVG, which is a *document* rather than a
   61 -- bitmap. Only SVG sets it, and the serving code must then attach
   62 -- 'svgHardeningCsp' — that header is what makes the document-navigation
   63 -- path safe. Splitting this out as a field (rather than string-matching
   64 -- @image\/svg+xml@ at the call site) keeps the requirement visible in the
   65 -- type instead of in a comment.
   66 data InlineMediaType = InlineMediaType
   67   { imtContentType :: Text
   68   , imtNeedsSvgCsp :: Bool
   69   } deriving stock (Eq, Show)
   70 
   71 -- | A raster image type: rendered as pixels, no document semantics.
   72 rasterType :: Text -> InlineMediaType
   73 rasterType ct = InlineMediaType { imtContentType = ct, imtNeedsSvgCsp = False }
   74 
   75 -- | The @Content-Type@ to serve @path@ with inline, or 'Nothing' when the
   76 -- extension is not on the allowlist (the caller then keeps the hardened
   77 -- @octet-stream@ + @attachment@ behaviour).
   78 --
   79 -- Matching is case-insensitive: @PHOTO.JPG@ and @photo.jpg@ are the same
   80 -- format, and a camera that writes upper-case extensions must not silently
   81 -- lose preview.
   82 inlineMediaTypeFor :: FilePath -> Maybe InlineMediaType
   83 inlineMediaTypeFor path
   84   -- A file whose whole name is the suffix (`.png`) is a hidden dotfile, not
   85   -- an image: `takeExtension "/home/u/.png"` yields @".png"@, so without
   86   -- this guard the stem would be empty and a dotfile would be typed as an
   87   -- image purely because of its name.
   88   | T.null stem = Nothing
   89   | otherwise = case T.toLower ext of
   90       ".png"  -> Just (rasterType "image/png")
   91       ".jpg"  -> Just (rasterType "image/jpeg")
   92       ".jpeg" -> Just (rasterType "image/jpeg")
   93       ".gif"  -> Just (rasterType "image/gif")
   94       ".webp" -> Just (rasterType "image/webp")
   95       ".avif" -> Just (rasterType "image/avif")
   96       ".bmp"  -> Just (rasterType "image/bmp")
   97       ".ico"  -> Just (rasterType "image/x-icon")
   98       -- SVG is a document, not a bitmap. Allowed here because the response
   99       -- also carries 'svgHardeningCsp'; the '<img>' render context alone is
  100       -- not sufficient (the file is reachable as a document too).
  101       ".svg"  -> Just InlineMediaType
  102         { imtContentType = "image/svg+xml"
  103         , imtNeedsSvgCsp = True
  104         }
  105       _       -> Nothing
  106   where
  107     name = T.pack (takeFileName path)
  108     ext  = T.pack (takeExtension path)
  109     stem = T.take (T.length name - T.length ext) name

  111 -- | The @Content-Security-Policy@ that makes serving an SVG inline safe.
  112 --
  113 -- Every directive is load-bearing, and the combination was chosen by
  114 -- measurement rather than by copying a snippet:
  115 --
  116 -- * @sandbox@ — no tokens. Strips scripting and gives the document an
  117 --   opaque origin, so even if a payload slipped through it cannot read
  118 --   cookies, storage, or make same-origin requests.
  119 -- * @default-src 'none'@ / @script-src 'none'@ / @object-src 'none'@ —
  120 --   defence in depth against script, @javascript:@ URLs, and
  121 --   @<object>@/@<embed>@ re-embedding.
  122 -- * @style-src 'unsafe-inline'@ — REQUIRED for fidelity, not a concession.
  123 --   @default-src 'none'@ alone drops an SVG's own @<style>@ block, and
  124 --   design tools routinely style by class rather than by presentation
  125 --   attribute. Measured: without this, a styled SVG renders with default
  126 --   BLACK fills (47k pixels changed). With it, byte-identical to no-CSP.
  127 --   Inline *styles* are not a script vector; @style-src@ is unrelated to
  128 --   execution.
  129 -- * @img-src data:@ — permits only inline (data-URI) images inside the
  130 --   SVG, so a drawing can embed a raster without phoning home.
  131 -- * @base-uri@ / @form-action 'none'@ — close the remaining document
  132 --   behaviours (link rewriting, form submission).
  133 --
  134 -- 'sandbox' cannot be delivered via @<meta http-equiv>@, so this must be a
  135 -- real response header.
  136 svgHardeningCsp :: Text
  137 svgHardeningCsp = T.intercalate "; "
  138   [ "sandbox"
  139   , "default-src 'none'"
  140   , "script-src 'none'"
  141   , "object-src 'none'"
  142   , "base-uri 'none'"
  143   , "form-action 'none'"
  144   , "style-src 'unsafe-inline'"
  145   , "img-src data:"
  146   ]
